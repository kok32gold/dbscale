# Support

DBScale is maintained in spare time. There is no paid support tier and no response deadline.

## Questions and bugs

Search the [open issues](https://github.com/kok32gold/dbscale/issues) first, then open a form:

- Something failed or the result looks wrong: bug report
- You want a capability: feature request
- You want another database engine: database adapter request
- You are stuck using it: question

Include the DBScale version, database version, operating system, and a synthetic reproduction. Do not paste credentials, production schemas, private SQL, API keys, or customer data.

Usage questions can wait. A bug that lets DBScale write to the source database or leak a secret should follow [SECURITY.md](SECURITY.md) instead of a public issue.

## What you can expect

- The latest code on `main` and the latest tagged release get attention.
- Older tags do not. The project is pre-1.0. See [docs/versioning.md](docs/versioning.md).
- Recommendations are proposals. DBScale does not apply them to your database, and a recommendation is not a promise that the change is safe in production.

## Conduct

Report a conduct problem by opening an issue labeled `conduct`, or through GitHub private vulnerability reporting when the report contains personal information. See [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

A personal email address is not published here. If you need one for a report that should not sit in GitHub, that address has to be added by a maintainer.
